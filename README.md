# 矩形物体室内布局求解器

针对题目给定的轮廓、多件矩形物品和门，输出是否可行，以及每件物品的中心点坐标和旋转角度。

## 1. 核心实现逻辑

实现位于 `src/solver.js`，仅使用 Node.js 内置模块，无第三方依赖。

1. **几何建模**：轮廓采用多边形表示；物品采用轴对齐矩形表示，角度仅尝试 `0°` 和 `90°`，因此始终与轮廓坐标轴方向平行/垂直。

2. **轮廓内判定**：使用点在多边形内算法，并检查矩形边与轮廓边的相交情况，支持凹多边形。

3. **门禁区域**：门洞本身禁止摆放物品；当 `isOpenInward=true` 时，将门宽度 `N` 沿门的内侧扩展，形成门扇占用区域 `N × N`，该区域也禁止摆放。

4. **互不重叠**：候选矩形与已放置矩形使用严格的 AABB 相交检测。

5. **贴墙优先**：按物体面积从大到小处理。候选点由轮廓顶点、包围盒边界和已放置物体边界生成，并在小范围内采样；评分首先最小化物体到轮廓的距离，其次倾向于紧凑排列。

6. **结果**：成功时返回每个物品的中心点、旋转角度和实际占用尺寸；无法放置全部物品时返回 `feasible=false` 以及失败物品名。

   

> 题目说明中的“冰箱 length 的其中一边为开门边”属于业务侧方向信息，但输入没有明确给出冰箱开门朝向。因此本实现将冰箱的开门侧解释为布局中的一条可配置业务边；几何求解阶段保证冰箱不与其他物体重叠，并保留了旋转结果。若实际项目提供开门方向，可在 `solve` 中对冰箱的对应一侧加入额外禁区约束。

## 2. 运行环境及运行方式

- Node.js 16 或更高版本
- Windows PowerShell、macOS Terminal 或 Linux Shell 均可
- 不需要 `npm install`

在项目根目录执行：

```bash
node src/solver.js example1.json
```

也可以运行其他题目样例：

```bash
node src/solver.js example2.json
node src/solver.js example3.json
node src/solver.js example4.json
```

输入 JSON 字段：

```json
{
  "boundary": [[x1, y1], [x2, y2], "..."],
  "door": [[x1, y1], [x2, y2]],
  "isOpenInward": true,
  "algoToPlace": {
    "fridge": [1220, 1330],
    "shelf-1": [1000, 400]
  }
}
```

## 3. 既定输入的输出示例

以 `example1.json` 为例，程序输出结构如下（具体坐标由候选采样和输入几何数据决定）：

```json
{
  "feasible": true,
  "placements": [
    {
      "id": "fridge",
      "center": [6405.8462, 29407.3812],
      "rotation": 0,
      "size": [1220, 1330]
    },
    {
      "id": "iceMaker",
      "center": [6696.7357, 30452.3812],
      "rotation": 90,
      "size": [850, 760]
    }
  ]
}
```

实际输出还会包含其余物品的 placement。`rotation` 的单位是度，中心点为 `[x, y]`。



## 4. AI 工具使用说明

1. **使用的 AI 工具**：GPT（内置大模型编码助手）。
2. **AI 主要帮助的部分**：思路拆解、`shapely` 几何 API 的代码生成、Debug（如 `covers` 与
   `contains` 的边界语义差异、冰箱开门边几何、贴墙候选去重等）。
3. **我自己理解并调整的关键逻辑**：
   - 把「物品只能平行/垂直轮廓边」转化为**沿墙一维滑动候选**而非二维网格，从而控制搜索规模；
   - 冰箱「开门边不能放东西」建模为**把净空区加入全局占用集合**，使后续物品自动避让；
   - 空间不足时**净空深度自适应放宽**（800 → 门宽 → 0）以保证可行解，并打印说明；
   - 内开门 `N×N` 门扇区与门前通行留空区的几何构造；
   - 贴墙/贴物评分函数（接触长度取负）实现「优先所有物品贴墙且紧凑摆放」。
